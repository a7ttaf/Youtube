# S2 Stack Integration & Local Recovery — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Recover local working tree, finish 3 in-flight PRs, integrate the 71-commit S2 multi-tenant stack to `main` via one merge PR, add a hardcoded `X-Tenant-Id: UMS` header to the frontend, and reconcile planning docs with reality.

**Architecture:** Six sequential phases. Local `main` is only ever fast-forwarded from origin. Each phase produces a stable end state. Every push/merge to remote is gated by a user checkpoint. Alembic heads are discovered live during integration; PR merge type is `--merge` (no squash, no rebase). Disposable PostgreSQL preferred for Alembic validation, SQLite as documented fallback.

**Tech Stack:** Python (FastAPI, SQLAlchemy, Alembic, pytest, ruff), TypeScript (Vite, React), PostgreSQL, GitHub CLI (`gh`), Git.

**Linked spec:** `Docs/superpowers/specs/2026-05-21-s2-integration-and-recovery-design.md`

## Rollback Procedure

1. Identify the integration merge commit SHA on main (recorded post-merge)
2. Branch off origin/main: `git checkout -b revert/s2-integration origin/main`
3. `git revert -m 1 <integration_merge_sha>` — mainline=1 because main is the first parent
